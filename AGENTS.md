# Repository guide

## Purpose and runtime

- This repository contains a long-running Telegram bot that monitors Twitch, YouTube, GoodGame,
  VK Play, and Kick livestreams and sends or updates Telegram notifications.
- The application targets Node.js 24 (`.nvmrc`) and TypeScript. Source lives in `src/`; `dist/` is
  generated by `tsc` and is intentionally ignored.
- MariaDB is the persistent store. Sequelize models live in `src/db.ts`; schema changes are applied
  by Umzug migrations from `src/migrations/` and recorded in `SequelizeMeta`.
- Production startup is `node dist/main.js`. Local self-hosting uses `docker compose up -d` after a
  `.env` has been created from `example.env`.

## Repository map

- `src/main.ts`: composition root. It creates the database, provider clients, checker, sender,
  Telegram chat handler, and HTTP server.
- `src/checker.ts`: periodic provider polling and reconciliation of channels/streams into MariaDB.
- `src/sender.ts` and `src/chatSender.ts`: per-chat notification queues and Telegram message
  send/update/delete behavior.
- `src/chat.ts` and `src/router.ts`: Telegram commands, callback queries, menus, and permissions.
- `src/db.ts`: all models, associations, persistence methods, and transactional stream updates.
- `src/migrator.ts`, `src/migrations/`: migration runner and ordered database schema changes.
- `src/webServer.ts`, `src/ytPubSub.ts`: internal HTTP endpoint and YouTube WebSub lifecycle.
- `src/services/`: provider adapters implementing `ServiceInterface` from `src/checker.ts`.
- `src/tools/`: shared networking, throttling, scheduling, Telegram, formatting, and collection
  helpers.
- `src/locale/`: English and Russian user-facing strings.
- `packages/noop/`: local override used to exclude obsolete Cypress request packages from the
  dependency tree. Keep it available to Docker and `npm ci`.

## Working rules

- Make source changes in `src/`, not `dist/`. Do not commit generated output, runtime logs,
  database volumes, `node_modules/`, `.idea/`, or `.env`.
- Never print or commit values from `.env`. Add new configuration keys to both `src/appConfig.ts`
  and `example.env`; update Docker configuration only when deployment behavior changes.
- Preserve the existing style: two-space indentation, single quotes, no bracket spacing, trailing
  commas, and a 100-column print width. Use named error codes through `ErrorWithCode` where callers
  distinguish expected failures.
- This is an interval-driven concurrent application. Preserve the existing in-progress guards,
  rate limits, batch sizes, timeout leases, and retry behavior unless the task explicitly changes
  them. A provider failure must not incorrectly mark channels or streams as removed.
- Avoid importing `src/main.ts` in isolated tests: it constructs and starts the application at
  module load. Pass a minimal typed or mocked `Main` dependency to units instead.
- Database identifiers for provider objects are namespaced by `src/tools/serviceId.ts`. Keep raw
  provider IDs at adapter boundaries and wrap them only in checker/database orchestration.
- When user-visible text changes, keep `src/locale/en.ts` and `src/locale/ru.ts` on the same key set
  and preserve `{variable}` placeholders expected by callers.

## Validation

- Install exactly from the lockfile: `npm ci`.
- Type-check without output: `npm run typescript:check`.
- Run lint and formatting checks: `npm run lint`. Use `npm run lint:fix` for automatic fixes.
- Build (cleans and regenerates `dist/`): `npm run build`.
- Run deterministic unit tests with `npm test -- --runInBand`. The default Jest roots exclude the
  existing Twitch live integration tests, which require provider credentials and network access.
- Prefer the narrowest relevant checks while iterating, then run type-check and formatting before
  handoff. Exercise database, Telegram, and live-provider paths only when suitable disposable
  credentials and infrastructure are explicitly available.

## Change discipline

- Keep patches scoped and preserve unrelated work in a dirty tree.
- For schema changes, add a new migration and review model types, `Model.init`,
  indexes/associations, all query methods, and compatibility with existing MariaDB data. Never edit
  an already applied migration.
- For Telegram behavior, account for private chats, groups/supergroups, linked channel chats,
  callback queries, localization, Telegram rate limits, and known API error classification.
- For polling or sending changes, verify the complete chain: provider raw IDs -> namespaced DB IDs
  -> stream reconciliation -> chat/stream queue rows -> Telegram messages.
